Shell实验代码层次的理解

6F · 2026-07-29 · 约 5 分钟

上一篇已经让你从概念上理清楚了Shell在解析命令之后，要控制进程、处理信号的过程的一些概念，而Shell本质是一个代码构成的程序。
要想要让程序真正实现其功能，要借助代码中，先辈为我们沉淀下来的函数工具、调用接口等……
所以，接下来，落到实处，我会介绍C代码中在这个过程需要用到的重要函数、他们的用法(输入、处理、输出)

信号发送函数——kill(pid，sig)的用法

和fork()/execve()类似，它是C代码可调用<signal.h>库中为程序提供的系统调用函数的一个。用法如下：
❶函数的输入：

a.pid：需要操作系统发送信号的进程名。若写成-pid，则表示对以该进程为组长的整个进程组发送信号
b.sig：需要发送的信号的信号名，上面7个都是

❷函数的处理：让操作系统，给该pid对应的程序发送sig信号。
❸函数的输出：
若信号发送成功，返回0
若信号发送失败，返回-1
❹例如：

kill(114514,SIGINT)

执行该函数时，会请求操作系统，向pid = 114514的进程，发送SIGINT的信号，默认情况(指没有自定义处理方式的情况)下，代号为114514的进程就会终止。

信号接受、自定义处理函数—— signal(sig,处理方式)的用法

❶函数的输入：

a.sig，想要自定义处理方式的信号
b.处理方式， 一种是：sig_IGN，忽略，另一种是，singal_hander，在这里填入另外一个函数。

❷函数的处理：
当进程在收到sig信号时，会调用这个singal_handler()函数，而不是执行默认处理动作
❸函数的输出：
设置成功，无返回值
设置失败，返回SIG_ERR
❹例如：

提前写好handler函数：
/* SIGINT 的处理函数 */
void handle_sigint(int sig) {
    stop = 1;
}
在主程序中写入自定义处理函数，即可在接受到SIGINT时调用相应处理函数了
int main(){
signal(SIGINT,handle_sigint);//不会立刻调用，而是在收到SIGINT时，自动调用
}

子进程状态变化监听函数waitpid(pid,*status,options)的用法

❶函数的输入：

a.pid：指定需要监听的子进程对象。又可以分为以下情况
1、 pid = -1，表示任意一个子进程
2、 pid = 0 ,表示同一个进程组的任意一个子进程
3、 pid > 0 ,表示PID =该值的哪个子进程
b.*status：状态指针，打包了子进程的所有状态信息。
为了获取状态中的信息，我们需要用到宏工具，其用法与函数相同，从打包的status中可以提取出来信息。
1、若status =NULL，表示我们不关注信息，常用于waitpid(-1,NULL,WNOHANG)回收任意僵尸进程
c.options：方式选择
1、options=0，表示：等待，直到一个进程被终止，回收它，然后返回。
2、options=WNOHANG(Wait No Hang)，表示：不等待，若已有一个子进程终止，则回收它并返回 PID；否则立刻返回 0
3、options=WUNTRACED，等待，直到发生两种情况：
❶一个子进程终止，回收，然后返回。
❷或一个子进程被暂停，不回收，直接返回。
4、options=WCONTINUED，等待，直到发生两种情况：
❶一个子进程终止，回收，然后返回。
❷或一个暂停的子进程被恢复运行，不回收，直接返回。

❷函数的处理：按照如上的options方式选择处理并返回
❸函数的输出(返回值)：

1.如果有子进程状态发生变化，就返回这个子进程的PID。
2.如果是WNOHANG选项，没有子进程状态发生变化时，返回0。
3.如果已经没有子进程了、或报错，返1。
