Shell的工作原理

Shell 本身是一个进程，它在自己的那块内存里跑着一个无限循环。

每一轮循环做三件事：

  1. 打印提示符，等你输入命令
  2. 读取、并解析你输入的命令
  3. 调用 fork() 让操作系统再开一个进程，然后子进程调用 execve() 把自己变成你要运行的程序

Shell程序运行中的相关概念

为了毫无歧义的描述Shell实验过程，我们需要理解清楚下面这些概念、以及概念的英文也
尤其重要(便于之后和代码相关联、建立联系)

注意！这些概念的英文也同样重要！因为所有代码都只能使用英文来描述它们！理解这些英文更容易你理解代码！

终端(Terminal)

终端是，提供文本输入、显示输出的窗口。
我们把指令输入在终端这个窗口上，Shell程序从终端读取、解析这个指令。
每条指令，一般占据终端的一行。所以指令也被称为命令行(Command Line)

进程 与 进程ID (PID)

进程是占用了一定的内存空间，正在运行中的程序。
在操作系统的程序中，为了便于管理和控制进程，我们需要为每一个进程“起一个”名字，这个名字就是PID(Process identity)，就像身份证、学号一样，pid是唯一标识某一进程的一串数字。

进程组 与 进程组ID (PGID)

有些进程之间有着紧密的关系，这些进程构成了一个进程组(Process Group)。每一个进程组有一个组长。

进程组也有名字，叫PGID(Process Group identity)，PGID = 该进程组组长的PID。

比方说，微信朋友圈的进程和微信整体的进程。我们想要在关掉微信进程的时候，把它的子进程朋友圈也给关闭。于是，操作系统把这类相互存在关系的进程可以看成是一个进程组，只需要发送一次信号，就能让组内的所有进程终止。

fork()函数与进程组的关系

fork()可以为一个(父)进程创建一个子进程。由于这个子进程和原来的父进程存在着绑定关系，即子进程由父进程复制、分支而产生，所以，操作系统会默认把子进程加入父进程所在的进程组中。

如果父进程是最起始的那个进程(父进程不是别的进程的子进程)，那么父进程就是这个进程组的组长。

作业(jobs) 与作业ID

作业是指：由Shell创建，用来执行一条命令的所有子进程。唯一标识作业的名字，就是JID(Job identity)
举个例子
》你在Shell中输入：sleep 100指令(这会启动一个等待100s，啥也不做的程序)
》shell会创建fork()一个子进程，然后execve(sleep,100,environ)，让Sleep程序代替子进程。
这个进程组可以清晰的如下表示：

shell                  ← Shell，本身不是 job
└── sleep 100          ← job 是shell创建的所有子进程(该条命令就只有一个子进程)

前台作业、后台作业

前台作业是指：占用着终端(让终端不能为别的程序服务了)，可以接受键盘输入、终端信号的作业。
后台作业是指：不占用终端，不能直接读取键盘输入的作业.

用户在可以用&来标识让Shell在后台执行这个命令。

如：sleep 100 &   # &符号表示让这个指令的进程任务不占用前台(终端)。

信号(Signal)

信号是操作系统内核给某一进程发送的信息
常见的信号有这些，可以先了解：

信号名 对应英文单词 让操作系统内核发送该信号的一般方法(也可以通过🌟kill这个信号发送函数，不要理解成“杀死”函数) 含义
SIGCHLD Signal Child 任意子进程的状态发生变化(❶由运行变为终止❷由运行变为暂停❸从暂停恢复运行)，(操作系统)内核都会检测到，并且向父进程发送信号
 通知父进程，子进程状态的发生变化
SIGINT Signal interrupt Ctrl+C、kill(pid,SIGINT) 请求中断当前前台进程
SIGTSTP Signal Terminal Stop Ctrl+Z、kill(pid,SIGTSTP) 暂停当前前台进程
SIGCONT Signal Continue kill(pid,SIGCONT) 让暂停的进程继续运行
SIGTERM Signal Terminal kill(pid,SIGTERM) 告诉pid进程正常退出
SIGKILL Signal Kill kill(pid,SIGKILL) 强制终止pid进程
SIGHUP Signal Hangup 关闭终端 通常导致关联进程终止

进程接受到信号，怎么办？

当一个进程收到了来自操作系统的信号，有两种处理方式：
1️⃣默认处理：收到SIGINT就中断结束，收到SIGTSTP就暂停，……
2️⃣用户自定义处理(非默认处理)：执行用户自定义的信号处理函数(Signal_handler)。

用户自定义信号处理 与 信号处理函数(Singnal_handler)

kill(pid,sig)是我们的程序中，可以调用操作系统发送信号的函数。
而singal(sig,处理方式)，是我们程序中，可以自定义一个进程收到某个信号后的处理方式的函数。他们都来自<signal.h>
这里的处理方式，可以是忽略SIG_IGN，也可以是一个信号处理函数(singnal_handler)，告诉进程，在收到sig信号后，去执行相应的函数。
