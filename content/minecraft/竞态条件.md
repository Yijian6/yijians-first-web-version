## 竞态条件(race condition)
我们在之前的处理过程当中，都完全没有考虑一个问题：子进程和父进程的执行先后顺序，究竟谁快谁慢、谁先谁后。我们是这样做的：
![[Pasted image 20260804083624.png]]
有两件事情正在我们的程序中并行：
1️⃣子进程完成`execve()`，执行新程序，过一会后新程序终止，操作系统发送SIGCHLD给父进程。
2️⃣父进程完成`addjob()`工作。

值得注意的是：这两个进程，是都存在的。那么，谁先跑呢？
如果子进程先跑完结束了，发送SIGINT，父进程先接收到`deletejob()`，但是因为父进程还没进行，没有`addjob()`，所以压根无可`delete()`，直接继续运行了。而过去了很久之后，父进程又执行`addjob()`，在进程中添加了一条“幽灵job”。因为不会接收到这条job永远不会被删除，占用着前台，导致`fgpid(jobs)=pid`陷入死循环，我们的终端始终在sleep(1),就会卡死终端界面。

至于到底哪个进程先跑、先结束。这设计到Linux操作系统内核究竟如何调度。而调度器的状态受到很多环境条件的影响。可以看看这段Claude的解释，他回答了，为啥我们的调度器每一次执行的父、子进程的顺序不一定一样：
![[Pasted image 20260804084124.png|494]]
如何解决这个问题呢？
我们一定要让父进程的`addjob()`发生在处理子进程结束SIGCHLD之前。
我们需要引入一个信号阻塞的新概念和信号阻塞函数`Sigpromask()`
### 信号阻塞
：暂时禁止某些信号被传递、处理。
这里，我们想要在子进程出现之前(`fork()`之前)阻塞 SIGCHLD信号，父进程`addjob()` 之后再解除阻塞。确保`addjob()`在`deletejob()`之前。
### 如何实现呢？使用`int sigprocmask(int how, const sigset_t *set, sigset_t *oldset)`信号阻塞名单修改函数
❶输入：
	a.`how`修改的方式选项：
		1、how = SIG_BLOCK，把 `set` 里的信号**追加**到阻塞名单（原来阻塞的不受影响）
		2、how = SIG_UNBLOCK，把 `set` 里的信号**从**阻塞名单里**移除**
		3、how = SIG_SETMASK，把把阻塞名单**直接替换**成 `set` 的内容
	b.`set`一个信号集合，需要修改阻塞的名单，类型是`sigset_t`。可以用这些函数来构造它：
```c
sigset_t set;
Sigemptyset(&set);          // 清空名单
Sigaddset(&set, SIGCHLD);   // 加一个信号
Sigaddset(&set, SIGINT);    // 还可以加更多
```
		1、set =NULL表示不做任何修改，只通过第三个参数查看当前阻塞的名单
	c.`oldset`修改之前的阻塞名单
		1、oldset = NULL，表示不关系之前的状态。
❷处理：按照`how`的方式，对阻塞的信号名单进行修改。
❸输出(返回值)：
	成功，返回0；
	失败，返回-1；
