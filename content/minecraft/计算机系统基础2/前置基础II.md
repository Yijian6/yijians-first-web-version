# 前置基础II
>前情提要：
    在前置基础I中，我们提到，程序就是按照一定顺序完成任务的流程。程序表达的方式有很多种。从自然语言的流程表、到C语言的代码，为了CPU能够执行，又被编译器编译成了机器指令。
这些都是“死的程序”，只是呈现了程序的理论内容、概念。
而想要客观上实际被执行，我们还需要满足一些客观物质条件。他们也是计算机的组成部件的一部分。
![[Pasted image 20260723150716.png|500]]
## 1️⃣CPU
CPU当然是必不可少的，它是理解机器指令，执行机器指令的工具。但，光有CPU还不够。程序要有地方放啊，以及程序过程产生的数据也要有地方放，就需要——
## 2️⃣内存
![[Pasted image 20260731152051.png|500]]

内存是电脑主板上的一个芯片，是用于存放数据的硬件。
有了内存，代码、数据、变量等等才可能被存储。

==综上，当计算机给一个程序分配了一块内存，CPU开始运行这个程序，这个程序就不再是一个“死的文件”了，我们把他叫做——进程。==

## **进程(Process)**：是占用了一定的**内存**空间，正在运行中的**程序**。

从定义中你也能看出来，**内存**是硬件层次，程序是软件层次。要想建立连接。就需要**操作系统程序**作为中介。

在计算机中，我们往往要有很多个进程。比如，**浏览器**看网页、**微信**聊天、**音乐播放器**放歌、**文件管理器**找文件。

这些不同的进程，占用着不同的内存(否则我的代码覆盖你的代码就乱套了)

那么，问题来了。我们的程序(**用户程序**)由C语言代码构成，如何能够调用操作系统的程序，来实现多**进程**？

操作系统的开发者，那些计算机的先辈们。在设计操作系统的时候，为我们写好了可以完成操作**系统调用**的函数库。
如：
- **Linux/Unix操作系统**(程序)中，开发者将那些函数放在了操作系统中的一个名为`<unistd.h>`(Unix Stdandard)的文件里。
于是，我们在**用户程序**的开头写上`#include <unistd.h>`就能够调用这些C函数，让操作系统运行核心程序，实现**调用操作系统程序**。

## 这类系统调用函数有哪些呢？
下面的两个例子都是C语言代码 `<unistd.h>`中的函数，实现了调用**操作系统**管理进程。

### `fork()`： 让操作系统在内存里再开一块地，复制当前进程，分叉出一个新进程(子进程)
>`fork`单词的本意是叉子，分叉，函数给人一种，克隆了一个一模一样的进程，但这个进程与原来的进程，被处理改变的方式不同，走向可能不同，形成分叉。

❶函数的输入：无
❷函数的处理过程：告诉**操作系统**执行以下动作：
	a.在内存里**开一块新的空间**
	b.把当前进程的内容（代码、数据）**复制**到那块新空间里，作为一个**新进程**(是原来进程的子进程)
	c.给**新进程**分配一个**ID编号**——pid(**P**rocess **id**entity)
	d.在**进程表**中登记好这个新进程的记录
❸函数的输出：
	a.操作系统给**父进程**返回子进程的id编号；
	b.操作系统给**子进程**返回0；
于是同样一段代码，被父、子进程运行的时候，就产生了分叉，如下
```C
pid_t pid = fork();     
// pid_t =pid type，是专门表示进程的id的数据类型 ，用它来保存fork()函数的返回值。
//从这行开始，有两个进程在各自执行这段代码，但是由于返回值不同(子进程返回0，父进程返回子进程的pid)，从而产生分叉。
if (pid == 0) {
    // 子进程走这里（因为它拿到的是 0）
} else {
    // 父进程走这里（因为它拿到的是 16234(比方说)）
}

```
### `execve(路径,参数,environ)`让操作系统把当前进程的内存里的内容清掉，换成另一个程序的内容，从头开始执行的函数
❶函数的输入：如下三类参数
	a.要**运行的程序**(目标程序)的**路径**，比如说：`"/bin/ls"` 
	b.**目标程序**需要的**参数**，比如`"-l"`/`"-d"`,……
	c.环境变量，一般存在`environ`这个全局变量里，所以直接写environ就可以。
❷函数的处理：让操作系统执行：
	a.把当前进程的内存中的内容(代码、数据)清空
	b.按照路径找到**目标程序**，向内存装入该程序的代码、数据
	c.从main()函数开始执行**目标程序**
❸函数的输出：
成功时，用**目标程序**替换了**当前程序**，没有返回值；
失败时，返回值是-1；
